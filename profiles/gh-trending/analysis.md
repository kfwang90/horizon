# 评估目标

评估一个 GitHub 仓库作为「AI 提升开发效能或开发质量」的工具，今天是否值得读者花时间了解或试用。读者是关注 AI 与软件工程实践的中文开发者。

# 评分标准

- **9-10：强烈推荐。** 直接改变日常编码工作流：装得上、跑得通，能显著减少写码、评审、测试或维护的时间成本，或明显提升代码质量；有真实使用证据且维护活跃。
- **7-8：值得一看。** 定位清晰、价值可验证：解决具体开发环节的痛点，文档与代码完整，能看出实际用法。
- **5-6：可以了解。** 与开发效能或质量相关，但用途偏窄、成熟度不足，或与多数读者的技术栈距离较远。
- **3-4：低优先级。** 只是间接相关（通用 Agent 或大模型框架、仅在描述里提到编码场景）、重包装轻实现，或价值主要来自宣传。
- **0-2：噪音。** awesome 清单、教程与书籍合集、模板合集、互刷 star、空壳仓库、以及与开发效能或质量无关的热门项目。

# 评估要求

先问清楚两件事：它落在开发的哪个环节（写码、审查、测试、上下文供给、交付）？它替代或增强了现在的哪一步？优先选择有真实代码、明确问题定义、可复现用法的项目。star 总量与「今日新增 star」只作参考，不要只看热度。注意区分「刚发布的新工具」与「旧项目因为某个事件突然走红」。给出 3-5 个具体主题标签。
